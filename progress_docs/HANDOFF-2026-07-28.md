## 2. What shipped

1. **The harness-killing panic** (`d89f89f`). `clean_html` searched a `to_lowercase()` copy and
   indexed the *original* with those offsets. `İ` (U+0130, 2 bytes) lowercases to 3, so a
   Galatasaray report with eleven of them walked off the end and **panicked the whole process** —
   all nine stages, every in-flight item orphaned. This, not the drain starving `requeue_stale`, was
   the source of the eleven stuck `running` rows. Zero panics in the 22 hours since.
2. **Ingest scaled back to one daily sweep at 02:00** (`8eb6e02`), with the RSS lookback widened
   12h → 24h *in the same commit*. They are coupled: the window is both the `when:` token and the
   client-side freshness cutoff, so a cadence wider than the window silently drops the gap.
3. **The ingest cut ranks by Google** (`7e814a7`). `-rss-limit` cut by publish date; it now cuts by
   `feed_rank`, matching what the read budget already did. `sortArticlesByDate` deleted.
4. **The regex tier retired** (`6e50c66`). `filterRSSArticles` was rejecting **50% of everything
   Google returned** and starving fifteen clubs to zero. Players stopped auto-vetting in the same
   commit — that was mandatory, not optional, since auto-vet's "exact match" premise existed only
   because the regex guaranteed it. `-rss-limit` 12 → 100 (one Google page).
5. **The Journalist corpus ceiling** — `LIMIT 40` ranked by `feed_rank`, presented by date. Selection
   is a relevance decision; presentation is a voice decision, and that query now makes only the first.
6. **Shared gemma3 slots** (`17ded43`). The Reader and graph were pinned 2+2; they now draw from a
   shared 4-slot budget, so the Reader expands into graph's idle slots and gives them back within one
   top-up pass.
7. **Two Mac permits** (config, 21:47). See §4.

The plan's caveat expected a growing backlog to be partly self-inflicted; instead it shrank, which

**The permit result — the headline win.** Measured with real concurrent requests:

| config | slots | processor | 2 requests | aggregate |
|---|---|---|---|---|
| 16384, 1 slot *(old)* | 1 | 100% GPU | 20.4s | 12.5 tok/s |

## 5. The remaining plumbing checklist, in priority order

- [ ] **`transfers` handler timeout — the only thing degrading.** 18 timeouts and 11 dead letters on
      2026-07-27, up from 2. `insider/mod.rs:2184` calls `vet_pair` — a model call — once per
      candidate pair in a loop; candidates come from news, and news went up 7×. The 1200s clock
      starts when the handler starts, not when it reaches the GPU, so items die *queueing*. It is a
      capacity leak, not just lost rows: a dead-lettered item has already spent real generations.
      **Highest value, independent of everything else.**
- [ ] **`VOICE_NUM_CTX` 16384 → 8192** — see §6, it has a precondition.
- [ ] **`requeue_stale` on its own interval** + a startup guard refusing to boot if
      `handler_timeout >= stale_lease`. Safety checked: `requeue_stale` is one unconditional UPDATE
      and 1200s < 1800s means a live handler always fails before its row is eligible. Nothing
      currently enforces that ordering and both are env-tunable. Largely defanged by the stagger
      (every resume runs a boot sweep) so it is hygiene, not urgency.
- [ ] **The Oracle barrier is still unverified in production.** Never got to it. Its messages are
      `debug!` and the service runs at `INFO`, so zero barrier lines is absence of evidence. Cheapest
      test: raise to `debug` for one sweep, grep `oracle barrier`, revert.
- [ ] **Retire the vestigial edition-grid scaffolding.** `defaultRSSEditions` and
      `footballTeamRSSEditions` are one entry each; `EditionsPlanned/Queried/Skipped`,
      `runRSSQueryPastLimit`'s `editionIdx` arithmetic and `teams_edition_capped` are machinery for a
      grid that no longer exists. Every log line reads `editions_skipped=0` because it cannot read
      anything else.
- [ ] **Offset the two cards' rest windows.** Both currently go dark together. Buys pipeline
      continuity, *not* throughput (each card still rests 1-in-3 either way), so it is worth least
      while queues are deep. Recommended shape: two systemd units split on `COGNITION_STAGES`.
      **Trap:** `COGNITION_STAGES` lives in `.env.local`, which loads *after* the unit's
      `Environment=` line and overrides it.
- [ ] **Two `article_read` dead letters** at `attempts=5` (`173300`, `176396`, `parse article
      evidence`). Pre-existing, unrelated, permanently stuck.

## 6. The size-reduction thesis, and the one number that gates it

Scott's position, and it is the right default: **the burden of proof is on the larger context, not
the smaller one.** 16384 was never justified against measured prompt sizes.

Measured over **2,264 real production prompts** (from `ollama.err`, `task.n_tokens`):

| min | median | p90 | p99 | max |
|---|---|---|---|---|
| 13 | **1,947** | 3,647 | 7,101 | **14,086** |

| ceiling | prompts truncated |
|---|---|
| 8192 | **13 (0.57%)** |
| 6144 | 48 (2.12%) |
| 4096 | 163 (7.20%) |

**Those truncation figures understate the problem, because the context must hold prompt AND output.**
The real prompt budget at ceiling `C` is `C - num_predict`, and the reservations are large:

| stage | `num_predict` |
|---|---|
| **narratives (Journalist)** | **4,000** |
| peak/rating | 2,000 |
| momentum | 1,200 |
| oracle / vibe / insider score | 1,100 |

So at 8192 the Journalist has only **4,192 tokens of prompt budget**, and ~7% of prompts already
exceed 4,096. Not a 0.57% problem — closer to one call in ten having its output squeezed.

**But the reservations are wildly oversized.** Measured over **14,319 real generations**:

| median | p90 | p99 | **max ever** |
|---|---|---|---|
| 316 | 1,218 | 2,058 | **2,806** |

**Nothing has ever generated more than 2,806 tokens.** `NARRATIVES_NUM_PREDICT = 4000` reserves
1,194 tokens above the all-time maximum on every call, and 1,942 above p99. **That is free context
budget — cutting it to 3,000 cannot truncate anything that has ever happened.**

### Three levers, and they must be pulled in this order

1. **`num_predict` — free, do it first.** 4,000 → 3,000 for narratives is still above the observed
   max. Frees 1,000 tokens of prompt budget at any ceiling, at zero risk.
2. **Prompt size — the big one.** Median is only 1,947; it is the fat tail (p99 7,101, max 14,086)
   that forces a high ceiling. The Reader-side bucketing in `PLAN-ingest-simplification.md` collapses
   six retellings of one story into a single storyline, which is aimed exactly at that tail.
3. **The ceiling — last.** Only safe once 1 and 2 have pulled `prompt + output` down.

**And the payoff compounds, which is why order matters.** Each halving of the ceiling potentially
buys another permit: 16384 → 1 slot at full GPU; **8192 → 2 slots, measured, 1.46×**; 4096 → likely 4
slots (KV would be 0.33 GB/sequence, so ~11 GB total). If bucketing brings p99 to ~2,500 and
`num_predict` to 3,000, then 6144 or even 4096 becomes viable and the win goes from 1.46× toward
~2.2×. Shipping the ceiling first forecloses that; shipping it last collects it.

`VOICE_NUM_CTX` is a **compile-time const** in `rust/src/route.rs` — a rebuild and deploy, not a
config flip. Per-request `num_ctx` overrides the server default, so changing the Mac plist alone
does nothing.

## 7. The prompt session — the final phase

Order fixed by Scott: **bucketing → context size → delete BGE.** Everything mechanical lands first.

**Bucketing does the sorting in the Reader, not the Journalist.** *"It's not the brain work, it's the
sorting work."* Sorting belongs on the 1070, which has headroom; synthesis belongs on the Mac, which
does not. Mostly already built:

- The Reader **already emits `story_type`** and it discriminates — over 2,809 reads: transfer 1,005,
  fixture 581, general 424, performance 293, injury 277.
- So **`news_articles.bucket` is derived twice.** The Journalist re-derives it as step n9 from a
  900-byte blurb; the Reader already knows, from the **full body**. Writing it from the Reader
  deletes n9 and shortens the narratives prompt *and* its output schema.
- **Second bucket: related stories.** Use the house closed-candidate-list pattern — numbered open
  storylines, attach by number or declare new. **Not free-text names**, which will not match
  themselves ("Saka injury" vs "Bukayo Saka hamstring") — that is the exact problem embeddings were
  solving. This also replaces `threads`' BGE centroid cosine, so it serves Phase 3.

**Model choice: ministral stays incumbent.** It produces shippable product. Nemo passed fixtures
37/37 vs 36/37 and *still* lost on live data — it put raw telemetry in user-facing prose
(`-19.1 over 4 samples`, `82/100 sentiment score`) where ministral turns it into narrative. Warm
decode is identical (9.85 vs 10.24 tok/s); nemo's entire 1.7×-per-call edge was writing 40% fewer
tokens. **So output length and model choice are separable, and only one of them costs voice** —
prompt work that tightens ministral captures most of that win for free.

**The exemplar to protect** — this is what "lean" must not destroy. It is dense, not long:

> Wolves' PEAK remains a defensive shell with no offensive spark—still clinging to a stable but
> uninspiring composite z-score while their Goals For (27 · 3rd pct, z -1.5) drags them into the
> bottom tier of attackers… but the Vibe has cratered harder—£38m for João Gomes didn't just leave a
> gap; it exposed Cesar Peixoto's pre-season chaos… The PEAK holds steady, but the Vibe is in
> freefall, and the tension between a technically sound (if dull) system and a crumbling backroom has
> fans bracing for a season where the numbers won't tell the whole story.

Four things it does: the PEAK/Vibe **divergence is the story**; numbers are **load-bearing inside
claims** rather than stated alone; it reaches **real-world causes** from the corpus; and the last
clause turns the divergence into a **forward stake**. Measure any shortening against "did we keep the
causal fusion", never against word count.

## 8. Traps that cost real time

- **`launchctl kickstart` restarts the JOB; launchd keeps its CACHED plist.** A plist edit does
  nothing until `sudo launchctl bootout system/<label>` then `bootstrap`. This produced a completely
  false "the permit isn't free" result. **Verify a plist change against the running process
  (`ps eww <pid>`), never against the file.** The file proves intent; `ps eww` proves effect. Also:
  `bootout` is asynchronous — running `bootstrap` immediately after can fail with
  `Bootstrap failed: 5: Input/output error`, and a plain retry fixes it.
- **Always send a system prompt when benchmarking.** ministral's chat template injects a ~551-token
  default identity block *only when none is supplied*, which read as "551 tokens of production
  overhead per call." Production always sends one: `prompt_eval_count` is 36 with, 564 without.
- **A green fixture gate does not clear a model.** Property checks test word counts and banned
  phrases; they cannot see "this reads like a stats dump." Any model decision needs a **live-entity
  A/B read by a human** — `eval --task momentum <entity>` with `COGNITION_ROUTE_<ROLE>_CANDIDATE`.
- **The ingest cadence and the RSS lookback must move together.** A window narrower than the cron
  period drops the gap twice over, silently and unrecoverably. Test-guarded now.
- **`ps %cpu` is not an idleness signal** for a 100%-GPU-offloaded model.
- **The deploy path is `rust/bin/`, and `cargo build` runs from `rust/`.** The repo root's `bin/`
  holds only `scoracle-api`. Watch cwd: a repo-relative `chmod`/path issued from `rust/` silently
  misses and takes the whole `&&` chain with it.
- **When aggregating `queue-depth.csv`, take ONE sample per hour.** Six samples an hour, so summing
  naively counts everything six times.
- **`git fetch` before trusting `main`.**
